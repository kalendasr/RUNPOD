# Skill: pdf

> Generate PDF documents (quotations/invoices). Roadmap §3's own worked
> example: "generate PDF quotations" for a construction-quotes SaaS.

## When the Planner selects this

Any project that needs to produce a downloadable/emailable document —
quotations, invoices, receipts, reports.

## What it provides

`packages/pdf`:

- `quotationSubtotal(lineItems)` — pure line-item sum, no PDF involved.
- `generateQuotationPdf(input)` — a one-page A4 PDF (header, from/to,
  itemized table, subtotal, optional notes), using `pdf-lib` (pure JS, no
  native/system dependency — works the same in the dev sandbox, a Docker
  build, and CI).

```ts
import { generateQuotationPdf } from "@hermes/pdf";

const bytes = await generateQuotationPdf({
  quotationNumber: "Q-1001",
  issuedBy: { name: "Acme Construction" },
  issuedTo: { name: "Client LLC" },
  lineItems: [{ description: "Foundation work", quantity: 1, unitPrice: 5000 }],
});
```

## Key decision: deliberately minimal, no styling system

One page, no letterhead image, no tax/discount logic, no theming. This is
the mechanism for "produce a valid PDF from structured data" — visual
polish belongs in a design-system skill layered on top (roadmap §13; not
built yet), not folded into this function's argument list. Resist adding
a `theme` or `logo` parameter here before that skill exists; it'll end up
duplicating whatever that skill decides.
